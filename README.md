# 팀플X실시간 협업 보드

> 아이디어를 모으고 → 정리하고 → 실제 할 일로 만드는 과정을, 팀원 모두가 **한 화면에서 실시간으로** 끝내는 팀 프로젝트 협업 도구입니다.

## 왜 만들었나요?

대학생 팀플은 보통 이렇게 흘러갑니다. 아이디어는 카톡에, 정리는 노션에, 일정은 캘린더에, 할 일은 엑셀에 흩어져 있고, 정작 **"그래서 누가 언제까지 뭘 하지?"** 에 닿기까지 시간이 많이 듭니다.

이 서비스는 그 흐름을 하나로 이어 줍니다.

- **흩어진 도구를 하나로.** 브레인스토밍, 마인드맵, 업무 분해(WBS), 일정, 투표, 채팅을 한 보드 안에서 해결합니다.
- **아이디어가 곧 할 일이 됩니다.** 채택한 아이디어를 버튼 한 번으로 담당자·기간·진행률이 있는 작업으로 바꿉니다.
- **복잡하지 않게.** 처음 쓰는 팀원도 바로 참여할 수 있도록 단계별로 묶은 단순한 툴바를 씁니다.
- **동시에 편집해도 안전하게.** 여러 명이 같은 보드를 만져도 충돌 없이 자동으로 합쳐지고, 실수는 `Ctrl+Z`로 되돌립니다.
- **제출까지 한 번에.** 간트차트로 일정을 확인하고, 작업 목록을 엑셀(CSV)로, 보드를 이미지·PDF로 내보내 보고서에 바로 씁니다.

## 핵심 흐름

```
① 브레인스토밍          ② 마인드맵 구조화            ③ WBS 작업 연결
아이디어 막 던지기  →  관련 아이디어 연결/정리  →  채택한 아이디어를 할 일로 "승격"
 + 메모 버튼            점끼리 드래그 + 정렬         → 작업으로 버튼
```

1. **아이디어 모으기** : 툴바의 **+ 메모**로 떠오르는 생각을 자유롭게 적습니다.
2. **마인드맵으로 정리** : 노드의 점끼리 드래그해 연결하고, **가로/세로 정렬**로 트리처럼 구조화합니다.
3. **작업으로 전환** : 채택한 아이디어를 고르고 **→ 작업으로**를 누르면, 위치와 연결은 그대로 둔 채 WBS 작업이 됩니다.

툴바가 이 ①→②→③ 단계로 묶여 있고, 부가 기능은 **더보기** 뒤에 접혀 있습니다. 빈 보드에서는 3단계 안내가 표시됩니다.

## 기능 한눈에 보기

| 분야 | 기능 |
|------|------|
| 아이디어·마인드맵 | 메모·사진 노드(겹치지 않게 자동 배치, 사진 크기 조절), 연결·드래그로 합치기, 선마다 다른 연결선 스타일, 자동 정렬, 실행 취소·다시 실행 |
| 작업 관리(WBS) | 작업 승격, 담당자·시작일·마감일·진행률·체크항목·첨부, 간트차트, 담당자별 보기, 마감 임박 알림, 대시보드 |
| 일정·의사결정 | 팀 캘린더(시간·담당자), WBS 마감·투표 마감 자동 표시, 투표 세션, 노드 투표 |
| 소통 | 방 채팅(안 읽은 메시지 배지 + 카카오톡식 안 읽은 사람 수), 노드 댓글, 실시간 커서, 접속자 목록 |
| 기록·관리 | 변경 기록과 팀원별 기여도, 초대·수락, 팀장 위임, 내보내기, 보드 나가기, 팀장 전용 보드 삭제(되돌리기 어려운 동작은 확인 문구 입력) |
| 내보내기 | 보드 이미지(PNG)·PDF, WBS 표(엑셀 CSV) |
| 개인 | 나만 보는 노트장·파일 보관함(기기 간 동기화) |
| 화면 | 좁은 화면·터치 화면 대응 |

## 주요 기능

### 아이디어 · 마인드맵
- **스티커(포스트잇) 메모** : 툴바의 **+ 메모**로 추가합니다. 제목과 내용(여러 줄, 저장은 `Ctrl/⌘ + Enter`), 4가지 색상(노랑/분홍/파랑/초록)을 고를 수 있습니다. 모서리를 끌어 크기를 바꿀 수 있습니다.
- **사진 노드** : 더보기 › **+ 사진**으로 참고 이미지를 올립니다(PNG/JPG/GIF/WEBP, 최대 5MB). 사진은 서버에 저장되고 보드에는 참조만 담깁니다. 사진을 클릭해 선택하면 **모서리 손잡이로 크기를 조절**할 수 있고(가로세로 비율 유지), 조절한 크기는 모든 팀원에게 같이 보입니다.
- **겹치지 않게 배치** : 메모·WBS 작업·사진을 새로 만들면 화면 가운데를 기준으로 **다른 노드와 겹치지 않는 가장 가까운 빈자리**에 놓입니다(노드 사이 20px 간격). 사진은 파일의 가로세로 비율로 높이를 미리 계산해 자리를 찾습니다.
- **빈 곳 더블클릭으로는 노드가 생기지 않습니다.** 실수로 노드가 생기는 것을 막기 위해 툴바 버튼으로만 만듭니다. 예전에 더블클릭으로 만든 아이디어 노드는 그대로 남아 있고, 더블클릭해서 내용을 고칠 수 있습니다.
- **연결과 합치기** : 점끼리 드래그해 연결하거나, 노드를 다른 노드 위로 끌어다 놓아 부모-자식으로 합칩니다. 놓기 전에 "여기에 합치기" 안내가 보입니다.
- **자동 정렬** : 가로(→)·세로(↓) 트리, 격자(▦) 줄맞춤. 드래그할 때는 20px 그리드에 맞춰집니다.
- **보기 편의** : 노드 크기 조절, 긴 내용 접기/펼치기, 미니맵.
- **연결선 스타일(선마다 따로)** : 더보기 › **🔗 선 스타일**에서 색상·굵기를 바꿉니다.
  - 연결선을 클릭해 선택한 상태면 **그 선만** 바뀝니다(여러 개는 `Ctrl/⌘ + 클릭`).
  - 아무 선도 선택하지 않았으면 **새로 만들 선의 기본 스타일**이 바뀌고, 이미 있는 선은 그대로입니다.
  - 바꾼 스타일은 모든 팀원에게 공유됩니다.
- **실행 취소 / 다시 실행** : `Ctrl+Z`로 되돌리고 `Ctrl+Shift+Z` 또는 `Ctrl+Y`로 다시 실행합니다(맥은 `⌘`). 툴바의 ↶ ↷ 버튼도 있습니다.
  - 노드·연결선의 추가, 삭제, 이동, 수정, 정렬이 대상입니다.
  - **내가 한 변경만** 되돌리고 다른 팀원의 변경은 건드리지 않습니다.
  - 노드 선택(클릭)은 기록되지 않고, 0.5초 안에 이어진 변경(드래그 한 번 등)은 한 번에 되돌립니다.
  - 입력창에서 글자를 고치는 중에는 브라우저의 글자 되돌리기가 그대로 동작합니다.

### 작업 관리 (WBS)
- **아이디어 → 작업 승격** : 선택한 노드를 WBS 작업으로 바꿉니다. 텍스트, 투표, 댓글이 그대로 이어집니다.
- **작업 정보** : 작업명, 담당자, **시작일·마감일**, 상태(할 일/진행/완료), 진행률, 세부 체크항목. 시작일이 마감일보다 늦으면 저장되지 않습니다.
- **자료 첨부** : 링크나 파일(최대 10MB)을 붙입니다. 파일은 서버에 저장되며 보드 멤버만 내려받을 수 있습니다.
- **한 번에 완료** : 노드의 체크박스로 완료 처리하면 진행률이 100%가 되고 제목에 취소선이 표시됩니다.
- **마감 표시** : 마감 3일 이내는 노랑, 지난 작업은 빨강으로 강조하고 `D-2`, `D-DAY`, `3일 지남`으로 표시합니다.
- **간트차트(타임라인)** : 더보기 › **📈 간트차트**에서 작업을 시작일~마감일 **기간 막대**로 봅니다.
  - 막대 색은 상태, 막대 안의 진한 부분은 진행률, 빨간 세로선은 오늘입니다. 마감이 지난 미완료 작업은 빨간 테두리로 강조됩니다.
  - 날짜가 하나만 있으면 하루짜리 막대로, 둘 다 없으면 "날짜 미정" 목록에 모입니다. 작업 이름을 누르면 편집 패널이 열립니다.
- **담당자별 보기** : 툴바 ③ 작업 옆 **👤 선택 상자**에서 `내 작업만`, `담당자 미지정`, 특정 담당자를 고르면 해당 작업만 진하게 보이고 나머지는 흐려집니다(숨기지 않음, 내 화면에만 적용).
  - 담당자 칸에 `철수, 영희`처럼 여러 명을 적으면 각자에게 걸립니다(쉼표·슬래시·가운뎃점·`&`로 구분).
  - "내 작업"은 담당자가 내 이름 또는 아이디와 **정확히 같은** 작업입니다.
- **마감 임박 알림** : 보드에 들어오면 완료하지 않은 작업 중 **마감이 지났거나 오늘·내일 마감인 작업**을 요약 카드로 한 번 보여 줍니다. 작업을 누르면 편집 패널이, "캘린더에서 보기"를 누르면 캘린더가 열립니다.
- **대시보드** : 전체 진행률, 상태별 작업 수, 지연 건수, **팀원별 업무 현황**을 한눈에 봅니다.

### 일정 · 의사결정
- **팀 캘린더** : 월별 달력에서 날짜별 일정을 추가·수정·삭제·완료 체크합니다. 연/월 단위로 이동합니다.
  - 일정마다 **시간**과 **담당자**를 넣을 수 있습니다(선택). 담당자는 보드 멤버 이름이 자동완성됩니다.
  - 같은 날 일정은 시간 순으로 정렬되고, 시간이 없는 일정은 하루 종일 일정으로 맨 위에 보입니다.
- **WBS 마감 자동 기록** : WBS에 마감일을 넣으면 캘린더 해당 날짜에 자동으로 나타납니다. 캘린더에서 체크하면 그 작업이 완료 처리되고, 마감일을 바꾸거나 작업을 지우면 캘린더에도 바로 반영됩니다.
- **투표 세션** : 질문과 선택지로 팀 투표를 엽니다. 여러 주제를 동시에 열 수 있고, 마감 시각이 지나면 자동 종료되며, 결과는 실시간 막대그래프로 보입니다.
- **투표 마감 자동 기록** : 마감 시각을 정한 투표는 캘린더 해당 날짜에 `투표 마감` 태그와 시각으로 자동 표시됩니다(진행 중/종료). 누르면 투표 창이 열리고, 투표를 지우면 캘린더에서도 사라집니다.
- **노드 투표** : 아이디어·작업 카드의 👍 버튼으로 우선순위를 정합니다(1인 1표).

### 소통
- **방 채팅** : 같은 보드의 팀원끼리 대화합니다. 오른쪽 위에 항상 떠 있는 💬 버튼으로 엽니다.
  - **내가 보낸 메시지는 수정·삭제**할 수 있습니다.
  - 채팅창을 닫아 둔 동안 다른 팀원이 보낸 메시지는 버튼에 **빨간 안 읽은 메시지 수**로 표시되고, 채팅창을 열면 읽음 처리됩니다. **내가 보낸 메시지는 세지 않습니다.**
  - **카카오톡처럼 메시지마다 안 읽은 사람 수**가 말풍선 옆에 숫자로 보입니다. 예를 들어 3명 방에서 한 명이 보내면 `2`, 한 명이 읽으면 `1`, 모두 읽으면 숫자가 사라집니다. 보낸 사람 본인과, 메시지가 올라온 뒤에 들어온 멤버는 세지 않습니다.
  - 읽은 위치는 보드에 저장되어 **다른 기기에서도 같게** 보입니다. 채팅창이 열려 있어도 브라우저 탭을 다른 곳으로 옮겨 두면 읽지 않은 것으로 남습니다.
- **노드 댓글** : 특정 아이디어나 작업에 의견을 남깁니다. 본인 댓글만 수정·삭제할 수 있습니다.
- **실시간 커서 · 접속 현황** : 다른 팀원의 마우스 위치가 이름표 달린 색깔 커서로 보입니다. 툴바의 **👥 접속 N**을 누르면 지금 들어와 있는 팀원 목록이 버튼 아래로 펼쳐집니다(색 점 + 이름, 내 이름 옆에 `나`). 다시 누르거나, 목록 바깥을 누르거나, `Esc`를 누르면 접힙니다.

### 변경 기록 · 기여도
- 더보기 › **🕘 변경 기록**에서 누가 언제 무엇을 바꿨는지 최신순으로 봅니다. 대상은 노드 추가·수정·이동·삭제, 연결, 댓글·투표, 일정입니다.
- 위쪽의 **팀원별 기여도**에는 사람별 기록 건수와 분포(추가·수정·삭제·댓글·일정)가 막대로 보입니다. 사람을 누르면 그 사람의 기록만 걸러집니다.
- 항목을 누르면 보드에서 해당 노드로 화면이 이동합니다.
- 드래그처럼 2분 안에 같은 대상에 반복한 변경은 한 줄로 묶이고(`×횟수`), 최근 500건까지 보관합니다.
- 기록은 이 기능이 들어간 뒤부터 쌓이며, 기여도는 **참고용 지표**입니다([보안 참고](#보안-참고)).

### 개인 공간 · 내보내기
- **개인 공간** : 화면 왼쪽 **🗂️ 탭**에서 여는 나만의 노트장과 파일 보관함입니다. 서버에 저장되어 **다른 기기에서 로그인해도 그대로** 보입니다.
- **이미지 · PDF** : 더보기 › **공유**에서 보드 전체를 PNG 또는 PDF로 저장합니다. 화면 밖 노드까지 한 장에 담깁니다.
- **WBS 표(엑셀 CSV)** : 더보기 › 공유 › **📋 WBS 표(엑셀 CSV)로 저장**. 번호, 작업명, 담당자, 상태, 진행률, 시작일, 마감일, 마감 현황, 세부 체크항목, 첨부·투표·댓글 수가 들어갑니다. 엑셀에서 한글이 깨지지 않게 저장되고, 수식으로 실행될 수 있는 칸은 글자로만 보이게 처리합니다.

### 보드 · 멤버 관리
- **보드 만들기** : 이름을 비워 두면 `새보드(1)`, `새보드(2)`…로 자동 이름이 붙습니다.
- **초대와 수락** : 팀장이 아이디로 초대하면, 팀원이 **수락해야** 입장할 수 있습니다. 거절하면 초대가 사라집니다.
- **팀장 위임** : 멤버 관리에서 참여자 옆 **팀장 위임**을 누르면 역할이 맞바뀝니다. 새 팀장 화면에는 더보기나 멤버 관리를 열 때 반영됩니다.
- **내보내기(강퇴)** : 멤버 관리에서 참여자 옆 **내보내기**를 누르면 그 사람의 접근이 바로 끊깁니다. 아직 수락 전인 초대는 **초대 취소**로 바로 취소됩니다.
- **보드에서 나가기** : 참여자는 멤버 관리의 **🚪 이 보드에서 나가기**로 스스로 빠집니다. 이 보드에 둔 개인 공간도 함께 지워지고, 다시 들어오려면 초대가 필요합니다. 팀장은 먼저 위임해야 나갈 수 있습니다.
- **보드 삭제(팀장 전용)** : 보드 내용, 멤버, 업로드 파일, 모든 팀원의 개인 공간이 함께 지워지며 되돌릴 수 없습니다. 그 보드를 열어 둔 팀원에게는 안내가 뜨고 보드 목록으로 이동합니다.
- **확인 문구** : 되돌리기 어려운 동작은 실수로 누르지 않도록 문구를 직접 입력해야 확인 버튼이 켜집니다. 띄어쓰기와 끝 마침표 차이는 허용합니다(`팀장 위임`도 통과).

  | 동작 | 입력할 문구 |
  |------|------|
  | 팀장 위임 | `팀장위임` |
  | 내보내기 | `내보내기` |
  | 보드에서 나가기 | `나가겠습니다` |
  | 보드 삭제 | `삭제하겠습니다.` |

### 모바일 · 터치 화면
- 폭이 좁은 화면(720px 이하)에서는 툴바가 압축되고(단계 이름·안내 문구 숨김), 오른쪽 패널은 화면 전체 너비로 열리며, 채팅 버튼은 오른쪽 아래로 옮겨집니다. 미니맵은 숨깁니다.
- 터치 화면에서는 마우스를 올려야 보이던 버튼(채팅·댓글·일정의 수정/삭제)이 항상 보이고, 노드 연결 점이 커집니다.

## 계정과 권한

| 역할 | 할 수 있는 일 |
|------|------|
| **팀장 (owner)** | 보드를 만든 사람(또는 위임받은 사람). 편집, 멤버 초대·강퇴, **팀장 위임**, **보드 삭제**. 나가려면 먼저 위임 |
| **참여자 (member)** | 입장, 편집, **스스로 나가기** (초대·강퇴·삭제 불가) |
| **초대 대기 (invited)** | 초대받았지만 수락 전. 입장 불가 |

- 로그인 아이디는 영문/숫자/밑줄 3~20자, 이름은 30자 이하, 비밀번호는 6자 이상 72바이트(영문 기준 72자) 이하입니다. 인증은 JWT(HS256 고정), 비밀번호는 bcrypt로 해싱해 저장합니다.
- 같은 아이디로 로그인을 **10분 안에 10번 틀리면** 그 아이디는 10분 동안 로그인이 막힙니다(같은 IP 기준). 배포 서비스의 프록시 뒤에서는 `TRUST_PROXY=1`을 넣어야 사용자 IP가 구분됩니다. 넣지 않으면 모든 요청이 같은 IP로 보여서, 누구나 남의 아이디를 10번 틀려 잠글 수 있습니다.
- 권한 검사는 화면이 아니라 **서버**에서 합니다. 참여자가 화면을 조작해도 보드를 삭제할 수 없습니다.
- **실시간 서버도 접속할 때 검사합니다.** 로그인 토큰과 보드 멤버 여부를 확인해 통과하지 못하면 연결을 거절합니다(토큰 없음·위조 401, 멤버 아님·초대 대기 403, 없는 보드 404). 연결된 뒤에도 2초마다 다시 확인해서, 강퇴되거나 나가거나 보드가 삭제되면 연결이 끊깁니다.
- 업로드한 사진과 첨부 파일도 해당 보드의 멤버만 올리고 내려받을 수 있습니다.

## 실행 방법

**Node.js 24를 권장합니다**(22.12 이상의 22.x 또는 24.x, `package.json`의 `engines`로 고정). 로컬에서는 내장 SQLite(`node:sqlite`)를 쓰기 때문에 별도 DB 설치나 네이티브 컴파일이 필요 없습니다. 개발과 테스트는 Node.js v24.21.0에서 확인했습니다. 터미널은 **3개**가 필요합니다.

```bash
# 0. 의존성 설치 (최초 1회)
npm install

# 1. 실시간 동기화 서버 → ws://localhost:1234
npm run server

# 2. 방/권한 관리 API 서버 → http://localhost:3001
npm run api

# 3. 웹 앱 → http://localhost:5173
npm run dev
```

브라우저에서 `http://localhost:5173`에 접속해 **회원가입 → 보드 만들기 → 팀원 초대** 순서로 시작합니다. 초대받을 팀원도 미리 회원가입해 두어야 합니다.

### 한 포트로 실행 (`npm start`, 배포용)

배포 서비스는 보통 포트를 하나만 열어 주고, 보드 내용(Yjs 문서)은 서버 메모리에서 함께 관리됩니다. 그래서 배포할 때는 API 서버와 실시간 서버를 한 프로세스·한 포트로 띄웁니다.

```bash
npm start            # 포트: PORT 환경변수 (없으면 3001)
```

| 용도 | 주소 |
|------|------|
| API | `http(s)://<호스트>/api` → 프론트의 `VITE_API_URL` |
| 실시간 연결 | `ws(s)://<호스트>/ws` → 프론트의 `VITE_WS_URL` |

- 로컬에서 `npm start`로 띄웠다면 프론트는 `VITE_API_URL=http://localhost:3001/api`, `VITE_WS_URL=ws://localhost:3001/ws`로 실행합니다.
- `npm start`와 `npm run api`는 둘 다 기본 포트가 3001이라 **동시에 띄우지 마세요.**
- 실시간 서버는 예전 주소 형식(`/<보드>`)도 그대로 받습니다.

### 배포 빌드 검사 (Vercel)

`VITE_API_URL`·`VITE_WS_URL`은 **빌드할 때 코드에 박히는 값**이라, 빠뜨리면 `localhost` 주소로 빌드된 사이트가 배포됩니다. 그래서 Vercel에서 빌드할 때(`VERCEL=1`, Vercel이 자동으로 넣음)는 아래 경우 **빌드를 멈추고** 이유를 알려 줍니다.

- 값이 없거나 비어 있음
- 주소 형식이 아님
- `https://`·`wss://`가 아님 (https 사이트에서 `http`·`ws` 연결은 브라우저가 막음)
- `localhost`·`127.0.0.1` 주소

`VITE_API_URL`이 `/api`로 끝나지 않으면 경고만 합니다. 로컬 `npm run build`는 값이 없어도 멈추지 않고 경고만 출력합니다. Vercel의 Environment Variables에 값을 넣을 때 **Preview 환경에도 체크**해야 미리보기 배포도 통과합니다.

또 `VITE_`로 시작하는 값은 브라우저에 그대로 공개되므로, 여기에 **서버 비밀 값**(Supabase Secret key `sb_secret_...`, 예전 `service_role` 키, `postgres://` 접속 주소, 이름에 `SECRET`·`PASSWORD`·`JWT`가 들어간 변수)이 있으면 로컬 빌드여도 **항상 멈춥니다.**

## 배포 (Vercel + Render + Supabase)

| 역할 | 서비스 | 하는 일 |
|------|--------|---------|
| 프론트엔드 | **Vercel** | `npm run build`로 만든 화면(`dist/`) |
| 백엔드 | **Render** (Web Service) | `npm start` — API + 실시간 서버 한 포트 |
| DB · 파일 | **Supabase** | Postgres(사용자·보드·보드 내용), Storage(사진·첨부 파일, 비공개 버킷) |

> Render 무료 플랜은 디스크가 재시작·재배포 때마다 지워집니다. 그래서 배포에서는 SQLite·`uploads/` 대신 **반드시 Supabase**에 저장합니다. 화면은 Supabase에 직접 접속하지 않고 모든 요청이 Render 서버를 거치므로, 권한 검사는 지금처럼 서버가 합니다.

### 1. Supabase

1. 새 프로젝트를 만듭니다. 지역은 **Northeast Asia (Seoul)** 를 권장합니다.
2. **Connect** › **Session pooler**의 주소를 복사해 DB 비밀번호를 채웁니다. 이것이 `DATABASE_URL`입니다.
   - `postgresql://postgres.<ref>:<비밀번호>@aws-0-ap-northeast-2.pooler.supabase.com:5432/postgres`
   - **Direct connection은 쓰면 안 됩니다.** IPv6 전용인데 Render는 IPv6로 나가지 못합니다(유료 IPv4 애드온이 있으면 가능).
   - 비밀번호에 `@`·`#`·`/` 같은 문자가 있으면 주소 안에서 `%40`처럼 바꿔 넣어야 합니다.
3. **Settings › API Keys**에서 **Secret key**(`sb_secret_...`)를 복사합니다. 이것이 `SUPABASE_SECRET_KEY`입니다. 예전 `service_role` 키도 동작하지만 새 키를 권장합니다.
4. 표와 버킷은 **서버가 처음 시작할 때 자동으로** 만듭니다. 표에는 RLS(행 수준 보안)가 켜지고 정책이 없어서, Supabase의 공개 키로는 데이터를 읽거나 쓸 수 없습니다. 버킷은 비공개(`public: false`)로 만들어집니다.

### 2. Render

저장소의 `render.yaml`로 **New › Blueprint**를 만들면 설정이 채워집니다. 직접 만들 때는 아래처럼 합니다.

| 항목 | 값 |
|------|-----|
| Build Command | `npm ci --omit=dev` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |
| 인스턴스 | **1대** (보드 내용·로그인 실패 기록이 서버 메모리에 있음) |

| 환경변수 | 값 |
|----------|-----|
| `NODE_ENV` | `production` |
| `JWT_SECRET` | 32자 이상 임의 값 (Blueprint는 자동 생성) |
| `DATABASE_URL` | 위 1-2의 Session pooler 주소 |
| `STORAGE_DRIVER` | `supabase` |
| `SUPABASE_URL` | `https://<ref>.supabase.co` |
| `SUPABASE_SECRET_KEY` | 위 1-3의 Secret key |
| `CORS_ORIGIN` | Vercel 주소, 예: `https://<프로젝트>.vercel.app` |
| `TRUST_PROXY` | `1` |

배포 로그에 `DB → Postgres (...pooler.supabase.com...)`와 `파일 저장소 → Supabase Storage`가 보이면 연결된 것입니다. DB나 저장소에 연결하지 못하면 서버는 이유를 출력하고 시작하지 않습니다.

### 3. Vercel

1. 저장소를 가져오면 Vite가 자동 인식됩니다(Build `npm run build`, Output `dist`).
2. Environment Variables에 **Production과 Preview 모두** 넣습니다.
   - `VITE_API_URL` = `https://<render 서비스>.onrender.com/api`
   - `VITE_WS_URL` = `wss://<render 서비스>.onrender.com/ws`
3. Vercel 주소가 정해지면 Render의 `CORS_ORIGIN`에 넣고 다시 배포합니다.

### 4. 기존 데이터 옮기기 (선택)

로컬 `board.db`와 `uploads/`에 있는 계정·보드·파일을 **비어 있는 Supabase**로 옮깁니다. 내 컴퓨터에서 한 번 실행합니다.

```bash
# 프로젝트 폴더에 .env.migrate 파일을 만들어 DATABASE_URL, STORAGE_DRIVER=supabase,
# SUPABASE_URL, SUPABASE_SECRET_KEY 를 적은 뒤
npm run migrate:supabase                 # 원본: board.db
npm run migrate:supabase -- other.db     # 다른 SQLite 파일이면 경로를 뒤에
```

- 대상 DB에 사용자가 이미 있으면 덮어쓰지 않고 멈춥니다. 표 옮기기는 한 번에 처리되어, 중간에 실패하면 대상은 비어 있는 그대로입니다.
- 원본 `board.db`·`uploads/`는 읽기만 합니다. `.env.*` 파일은 커밋되지 않습니다(`.gitignore`).
- 옮긴 뒤에도 기존 비밀번호로 로그인되고, 보드 안의 사진 참조(`fsafile:`)도 그대로 동작합니다.

### 배포 뒤 확인한 것

실제 배포된 주소(Vercel·Render·Supabase)로 아래를 확인했습니다. 확인에 쓴 계정과 보드는 끝난 뒤 지웠습니다.

| 항목 | 결과 |
|------|------|
| 화면 | 사이트가 열리고, 번들에 Render 서버 주소가 들어 있음(`localhost` 없음) |
| CORS | Vercel 주소만 허용, 다른 사이트는 거절 |
| 계정·보드 | 회원가입, 로그인, 보드 만들기, 초대·수락 |
| 사진 | Supabase Storage에 올리고 다른 팀원이 내려받으면 원본과 같음 |
| 실시간 | 두 사람이 접속해 한쪽 수정이 다른 쪽에 바로 보이고, Supabase DB에 저장됨 |
| 보드 삭제 | DB 기록과 Storage 파일까지 함께 지워짐 |
| 보안 | 표 6개 모두 RLS 켜짐, 파일 버킷 비공개 |
| `TRUST_PROXY=1` | 아래 참고 |

**`TRUST_PROXY` 확인 방법** : `DEBUG_IP_ECHO=1`로 잠깐 배포한 뒤 `GET /api/debug/ip`가 돌려준 IP를 내 실제 공인 IP와 비교하고, `X-Forwarded-For` 헤더를 꾸며 보내도 결과가 바뀌지 않는지 봅니다. 확인이 끝나면 `DEBUG_IP_ECHO`를 지우고 다시 배포합니다.

### 배포 전 확인할 점

- **Render 무료 플랜은 15분 동안 요청이 없으면 잠듭니다.** 다음 접속 때 깨어나는 데 수십 초가 걸리고, 그동안 실시간 연결이 다시 시도됩니다. 발표·시연 전에는 미리 한 번 접속해 두세요.
- 서버 재배포 때는 `SIGTERM`을 받아 열려 있는 보드를 저장한 뒤 끝냅니다. 그래도 저장 직전 1초 안의 변경은 다시 접속한 사람의 화면에서 다시 보내집니다(Yjs).
- 서울·뭄바이 Supabase와 가장 가까운 Render 지역은 **Singapore**입니다(`render.yaml` 기본값).
- Render는 `package.json`의 `engines`를 보고 Node 버전을 고릅니다. 범위를 열어 두면 테스트하지 않은 최신 버전이 쓰일 수 있어 22.x·24.x로 고정했습니다.
- 자동 배포가 켜져 있어 GitHub `main`에 올리면 Render와 Vercel이 각각 다시 배포합니다.
- Supabase 무료 플랜은 일주일간 사용이 없으면 프로젝트가 일시 정지될 수 있습니다. 대시보드에서 다시 켤 수 있습니다.

## 데이터 저장

- **DB**는 로컬에서는 SQLite(`board.db`), 배포에서는 Postgres(Supabase)입니다. `DATABASE_URL`이 있으면 Postgres를 씁니다. 같은 코드가 두 DB에서 똑같이 동작하는지 자동 테스트로 확인합니다.
- **보드 내용**은 보드별로 `docs` 테이블에 저장됩니다. 변경 후 약 0.8초 뒤 자동 저장되고, 모든 참여자가 나가면 한 번 더 저장됩니다. 서버를 껐다 켜도 복원됩니다. 불러오기가 끝나기 전에는 저장하지 않아서 빈 보드가 기존 내용을 덮어쓰지 않고, 모두 나간 직후 다시 들어와도 마지막 저장이 끝난 뒤에 불러옵니다.
- **사진·첨부 파일**은 로컬에서는 서버 디스크(`uploads/<보드>/`), 배포에서는 Supabase Storage 비공개 버킷에 저장합니다. 보드 문서에는 `fsafile:<보드>/<파일id>` 참조만 넣습니다. 그래서 파일 때문에 보드가 무거워지거나 DB가 불어나지 않습니다. 예전 방식으로 문서에 직접 들어간 사진도 그대로 보입니다.
- **개인 공간**은 같은 DB의 `personal_spaces` 테이블에 사용자+보드별로 저장됩니다.
- **화면 상태**(노드 선택, 담당자 필터)는 공유하지 않고 각자의 브라우저에만 둡니다. 채팅 읽은 위치는 읽음 숫자를 위해 보드에 공유 저장합니다.
- `board.db`와 `uploads/`는 `.gitignore`로 커밋에서 제외됩니다. 로컬 데이터를 Supabase로 옮길 때는 `npm run migrate:supabase`를 씁니다([배포](#4-기존-데이터-옮기기-선택)).

## 보안 참고

- **`JWT_SECRET`** : 기본값은 개발용입니다. 배포할 때는 반드시 긴 임의 값으로 바꾸세요. `NODE_ENV=production`에서 값이 없거나, `.env.example`의 예시 값이거나, 32자보다 짧으면 서버가 시작을 거부합니다.
- **공유 문서의 주소 검사** : 보드 문서는 멤버라면 누구나 직접 고칠 수 있으므로, 화면에 보여 줄 때 다시 검사합니다. 첨부 링크는 `http(s)`와 서버 파일만, 사진은 서버 파일과 이미지 data URL만 씁니다(`javascript:` 주소, 외부 추적용 이미지 차단).
- **서버 입력 검사** : 문자열이 아닌 값이나 너무 긴 값은 400으로 거절하고, 내부 오류 문구(DB·파서 메시지)는 응답에 담지 않습니다. 일반 API 요청 본문은 1MB, 개인 공간 저장은 로그인한 멤버만 20MB까지 받습니다.
- **HTTPS / WSS** : 실시간 연결은 라이브러리 구조상 로그인 토큰을 접속 주소(`?token=`)에 붙여 보냅니다. 배포할 때는 꼭 `https`·`wss`를 쓰고, 서버 접속 기록에 주소 전체가 남지 않게 설정하세요.
- **변경 기록의 신뢰도** : 기록은 각 팀원의 브라우저가 자기 변경을 남기는 방식입니다. 화면을 조작해 만든 기록까지 서버가 막지는 않으므로, 기여도는 평가의 근거가 아니라 참고용으로 써 주세요.
- **업로드 파일** : 사진은 PNG/JPG/GIF/WEBP만 받고(SVG 차단), 그 밖의 형식은 브라우저에서 실행되지 않도록 항상 다운로드로만 내려줍니다.
- **채팅 읽음 숫자** : 읽은 위치도 각 팀원의 브라우저가 기록합니다. 변경 기록과 마찬가지로 서버가 보증하는 값은 아닙니다.
- **의존성 보안 경고** : 배포되는 코드에 들어가는 패키지는 `npm audit --omit=dev` 기준 **0건**입니다. jsPDF는 4.2.1로 올렸습니다. 전체 `npm audit`에 남은 6건은 개발·테스트 도구에만 해당합니다.
  - `vite`·`esbuild`: 개발 서버(`npm run dev`)에만 해당합니다.
  - `vitest`·`tinypool` 등: 테스트 실행에만 해당합니다.
  - 모두 메이저 버전 업그레이드가 필요해 따로 진행할 예정입니다.

## 현재 한계

- 화면(React 컴포넌트)을 브라우저로 직접 눌러 보는 자동 테스트는 아직 없습니다. 모바일 화면도 실제 기기에서 충분히 확인하지 못했습니다.
- 실행 취소 기록은 보드를 나가거나 새로고침하면 사라집니다. 내가 바꾼 노드를 다른 팀원이 그 뒤에 다시 고쳤다면, 그 노드에 대한 내 변경은 되돌려지지 않습니다(남의 작업을 덮어쓰지 않기 위함).
- 개인 공간의 파일은 아직 DB에 직접 저장됩니다(보드 파일과 달리 서버 디스크로 옮기지 않음).
- 담당자는 자유 입력이라, 이름을 다르게 적으면 "내 작업" 필터와 대시보드 집계가 따로 잡힙니다.
- 새 노드 자리는 만들기 전의 예상 크기로 찾습니다. 메모·작업 내용이 아주 길면 실제로 커지면서 옆 노드와 조금 겹칠 수 있습니다.
- 채팅 읽음 숫자는 이 기능이 들어간 뒤부터 정확합니다. 그 전에 쌓인 메시지는 각자 채팅창을 한 번 열면 정리됩니다.
- 접속자 목록의 `나` 표시는 이름으로 판단해, 같은 이름의 팀원이 있으면 둘 다 `나`로 보일 수 있습니다.
- 서버는 **1대로만** 운영할 수 있습니다. 열려 있는 보드 내용과 로그인 실패 기록이 서버 메모리에 있어서, 여러 대로 늘리면 서로 다른 사람이 같은 보드를 따로 보게 됩니다.
- 배포 서버(Render 무료 플랜)는 쉬는 동안 잠들어서, 오랜만의 첫 접속은 30초~1분쯤 걸립니다.
